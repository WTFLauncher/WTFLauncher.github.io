WTF Launcher

基于 Prism Launcher 的开源 Minecraft: Java Edition 启动器，为国内网络环境做了下载镜像、Java 自动配置与 OptiFine 支持。

它解决什么问题

国内玩家用通用启动器时最常碰到三件事：Mojang 的下载端点慢或连不上、Java 运行库要自己找、以及模组与整合包的下载入口不好用。WTF Launcher 不改动上游的功能结构，只在这三点上补齐，并且把所有下载行为都留在玩家自己的机器与官方端点之间。

当前功能

  • 实例管理：每个实例独立目录、独立版本组件，支持导入导出与模组、资源包、世界的浏览与下载（Modrinth 与 CurseForge）。作者不允许第三方启动器转发的模组文件，默认不去别的源补下载，这个选择写在设置里，默认关闭。
  • 下载镜像：游戏本体、资源文件、支持库三类分别配置镜像源与尝试顺序，任一源失败自动按序回退，官方源始终保留为最后兜底。详见下一节。
  • Java 自动配置：按版本要求自动选择或下载 Java 运行库，可限定允许的 Java 版本区间，也支持把 Java 放在实例目录内优先使用。版本通过实际运行程序确认，不按目录名猜测。
  • 内存与 JVM 参数建议：按这台机器的内存和这个实例的模组数量给出堆的大小，并可一键填入垃圾回收参数；填入时会保留你自己写过的参数，只替换其中被建议覆盖的同一项。
  • 启动失败诊断：游戏没能启动时读取日志，认出内存不足、Metaspace 不足、Java 版本与模组不匹配、模组重复或缺依赖、mixin 失败、显卡驱动打不开窗口、纹理图集溢出等具体是哪一条，并给出对应的改法。
  • 服务器列表：实例内的服务器按 SLP 协议探测，显示在线人数、游戏版本与延迟，鼠标停在一行上能看到服务器自己的欢迎语。
  • OptiFine：在版本页直接浏览并安装 OptiFine。安装使用 OptiFine 官方安装器本身，启动器只负责下载、在临时目录中运行它并收集结果，不复制、不重制 OptiFine 的任何补丁逻辑。
  • 模组加载器：NeoForge、Forge、Fabric、Quilt、LiteLoader，与上游一致。
  • 中文界面：翻译由本项目自建的静态源提供，启动时校验文件哈希后加载。

下载镜像是怎么做的

镜像只做一件事：把下载请求换成另一个主机上的同一份文件。路径规则按内容类型固定，且只对 Mojang 自己的主机生效。

内容官方主机镜像上的位置
版本清单、客户端 jar、Java 运行库piston-meta / piston-data / launcher / launchermeta镜像根路径，目录结构不变
资源文件（assets）resources.download.minecraft.net镜像的 /assets 前缀
支持库与加载器库libraries.minecraft.net 等 maven 主机有序的前缀列表，逐条尝试

内置的镜像源为 BMCLAPI 与三所教育网镜像的 maven 树。Modrinth、CurseForge 等内容平台的主机不在重写范围内，它们的文件始终从各自官方端点下载。所有下载都会校验元数据里给定的哈希，镜像返回错误内容会被当作校验失败处理，而不是静默接受。

账户与登录

  • Microsoft 账户：走标准 OAuth 2.0（授权码 + PKCE 与设备码两种流），随后按官方流程换取 Xbox Live 与 Minecraft Services 令牌，并读取账户的游戏所有权信息，之后才提供启动。使用微软登录需要一个已通过 Mojang 应用登记的 AppID；本仓库自带的 AppID 尚未通过登记，因此该路径在默认构建里不可用，登录界面会明确提示，用户也可以自行填入已授权的 AppID。
  • 离线账户：显式的本地身份，只在本地生成玩家名与 UUID，用于单机世界与允许离线玩家的服务器。它不向 Microsoft、Realms 或需要正版验证的服务器认证，也拿不到任何 Microsoft 或 Minecraft 令牌；在线会话失败或过期时不会回退成离线账户。与上游 Prism 相同，只有在已添加一个拥有 Minecraft 的微软账户之后才能新建；启动与下载以拥有游戏的微软账户或第三方验证账户为准。
  • 第三方账户：向玩家自己填写的身份验证服务器（运行 authlib-injector 或同类实现的服务器）换取游戏令牌。地址填服务器给玩家的那个验证地址，启动器在它下面接 authserver/authenticate 这类路径，不需要也不应该自己补全；以 LittleSkin 为例，填它给出的形如 https://littleskin.cn/api/yggdrasil 的地址即可。这个账户上有多个角色时，登录会先问要哪一个，之后每次登录都按这个选择去要。令牌与角色名保存在本地；服务器拒绝登录时，显示它自己给出的原因。登录凭据以明文保存在本机的账户文件中，因为该协议只在换取令牌时接受账号密码。实例还需要 authlib-injector 代理，用这类账户启动时启动器会询问并代为安装为实例组件。

隐私

  • 没有自建的分析服务，不收集使用数据、不上传实例内容。
  • 网络请求只发往：Mojang 与微软的官方端点、玩家配置的镜像、Modrinth（模组浏览）、玩家自己添加的身份验证服务器，以及玩家自行配置的翻译源。
  • 游戏截图分享（Imgur）在本项目中未配置，功能默认不启用。

For the Minecraft / Mojang app review team

What this is. WTF Launcher is a free, open-source Minecraft: Java Edition launcher for players in mainland China, a GPL-3.0 derivative of Prism Launcher. Everything is published in the repository linked above; there is no closed or obfuscated component, and no binaries are hosted anywhere else.

What we are asking for. Approval of our own application (client) ID for the Java game service APIs, so that our users can sign in with their own Microsoft accounts inside our launcher.

The authentication chain we implement. Authorization code with PKCE, or the device code flow, against the Microsoft identity platform. The launcher requests Xbox access, obtains the Xbox Live and XSTS tokens, exchanges them at login_with_xbox, and checks the player's Java profile and Minecraft license. Only an account that passes that check counts toward launching or downloading. The tokens it is issued are kept in the launcher's local account file so the player does not sign in on every launch, and are sent only to the official Microsoft, Xbox Live and Minecraft Services endpoints. It does not use those endpoints to obtain game content for redistribution.

Why our own ID rather than an existing one. Upstream Prism Launcher's source states that a derivative work must ship its own credentials. Using another project's application ID would attribute our traffic to them and leave them unable to revoke it; we hold our own.

Load on your servers and CDN. API calls happen only when a player opens an account, browses, or launches. One game file download per version per player, from Mojang's own endpoints. No crawling, no bulk indexing, no background polling, and no redistribution of downloaded files from our side — the mirrors we ship rewrite Mojang-hosted file URLs only, and are used solely by the individual player who enables them.

Local profiles, stated plainly. Offline profiles are explicitly local identities for singleplayer worlds and for servers that allow offline players. They do not authenticate to Microsoft, Realms, or servers that require online accounts, and they receive no Microsoft or Minecraft token. One can be created only after an account that owns Minecraft has been added, and a failed or expired Microsoft sign-in never falls back to an offline profile. Separately, a player may point the launcher at a server operator's own authentication service; that service is added by the player, never contacts Microsoft, and is not part of the Microsoft sign-in path.
